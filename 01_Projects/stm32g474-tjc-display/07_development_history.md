## Phase Notes

### Phase 1：从独立显示演示开始

最初只有淘晶驰显示演示与队友信号处理代码，两边的外设初始化、`main.c`和数据
结构都不同。早期正确决定不是把两个主程序拼在一起，而是保留算法完整工程作为
底座，把显示代码拆成独立模块。该阶段解决了曲线ID写死、页面切换、数字格式化和
HMI首次握手等基础问题。

### Phase 2：dashboard单页面和实体控制

双页面方案在状态同步、曲线ID和刷新时序上复杂，随后收敛到dashboard单页面。
屏幕现场不可触摸，因此KEY1成为主要入口。按键中断只记录时间和事件，短按/长按
在主循环解释，并复用原HMI命令处理路径，避免出现两套互相漂移的显示状态机。

### Phase 3：原始ADC相位折叠路线

项目曾尝试把原生ADC点按估计频率折叠到单周期，并逐步加入触发、Huber和已识别
谐波投影。离线工具发现低分母有理共振会导致相位槽覆盖稀疏；估计频率稍有偏差
还会让“计算覆盖率”看似很好而波形实际失真。这个阶段留下了波形实验室、覆盖率
扫描和真实ADC数组验证方法，但最终产品没有继续沿用普通/Huber双模式。

### Phase 4：真实ADC与显示桥接

V1.9以后坚持以队友采集分析工程为底座。桥接层负责把算法结果转换成稳定快照，
显示层不再读取FFT全局缓冲或自行推断测量值。此阶段修复了大型局部结构体导致的
主栈溢出、ArmClang半主机BKPT、FFT高负载期间USART3 ORE、曲线左右方向以及
频谱局部失败阻断全部文本等问题。

### Phase 5：双ADC 4096点升级

队友新工程使用TIM3双边沿触发ADC1/ADC2，各2048点交错为4096点浮点电压。
早期接口曾把2048点指针按4096点读取，且可能对已经是V的`VO`重复执行ADC码换算。
V2.5改为显式接收4096点电压，并把共享数组会被`Vpp_R()`原地修改的问题拆成
Prepare/Publish两阶段。V2.6加入Goertzel相位和前级相位补偿入口。

### Phase 6：从折叠转向幅相解析复原

队友`getup()`能根据有效分量的幅值和相位生成4096点理论周期，同时给出Upp；
第二次FFT产生Vr和最终频谱。项目一度尝试保留新旧模式开关，随后因代码量、交互
复杂度和路线重复决定完全废弃旧普通/Huber链。显示只消费解析波形，桥接固定抽取
512点。复合波形多峰会让“寻找最大峰”触发跳到另一周期，最终改为模型相位原点。

### Phase 7：无信号、单频和最终报告

前置电路空载时，噪声仍可能被固定峰数算法解释成正弦。最终链增加显式无信号
发布，不能用“拒绝本帧”保留上一幅波形；单频也成为独立状态，不再伪造第二峰。
报告部分把ADC和显示数学链写入官方模板，公式使用原生OMML，并在不超过8页的
正文约束下加入电路说明、主程序流程图和MCU—显示屏时序图。

### Phase 8：现场最终`24`与赛后定位

赛末形成名为`24`的完整工程。赛后核验发现：外部资料目录`24`与仓库
`teammate/24`的346个文件完全一致；较早`teammate/current`有16处差异；
`firmware`虽包含相同桥接/显示核心，但`main.c`不同。因此最终源码真源冻结为
仓库`teammate/24`，外部目录只保留原始备份和比赛资料。

### Phase 9：比赛结果与结题

官方获奖名单`Sheet1`第142行记录B26244、G题、北京交通大学、二等奖。项目按
省级二等奖结题。赛后入库重点从“下一版怎么开发”转为“如何复现实赛、哪些路线
已经废弃、证据在哪里、以后怎样避免把Git标签和现场最终包混为一谈”。

## Lessons By Stage

1. 多人嵌入式融合先选完整外设底座，再用接口接入模块，不能拼主程序。
2. HMI对象数字ID、页面生命周期和UART应答都属于协议，不是纯布局细节。
3. 相位折叠的可靠性受采样率有理关系和频率估计误差限制，不能只看插值平滑。
4. 高频采集、FFT与串口显示并存时，栈、共享缓冲覆盖和中断分工比算法公式更容易致命。
5. 稀疏解析模型适合题目限定信号，但必须显式处理无信号、漏峰、削顶和标定残差。
6. 报告中的公式实现误差不能冒充模拟前端和双ADC的实测精度。
7. 现场最终包可能晚于最后Git标签；结题必须用文件树和哈希重新确定真源。
